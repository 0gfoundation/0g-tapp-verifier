Layer 3 of the verification stack: a cache. Every result below is as of the time shown — a node may have restarted since, which changes its signer and resets its RTMRs. To verify a node yourself instead of trusting this page, use tapp-cli verify-app (layer 2) or run your own trustee (layer 1).
teeUrl is how a verifier finds a node at all — the registry's only pointer to where evidence can be fetched. It does not need to be attested, because getting it wrong cannot pass silently: a dead or mistyped address yields no evidence, and an address serving some other instance yields evidence whose signer does not match the registration. What a verdict rests on is the signer: the quote proves a genuine TDX platform holds that key and booted a particular image, and only the signer registered on chain can obtain the app's KMS key. The key follows the signer, not the address — so a relay forwarding a genuine node's evidence cannot make a conclusion false, and any location read off an IP is a guess rather than part of the verdict.
Evidence carries no challenge (0g-tapp#76), so "as of" means "when we received a blob claiming this", not "when the node was in this state".
Platform TCB is reported, never used to fail a node. Host firmware belongs to the cloud provider, not to the app's owner, and providers take Intel's updates on their own schedule — so a stale TCB is the normal state, and rejecting on it would mark every node red and tell you nothing. It is not nothing either: the advisory ids differ widely in how much they bear on TDX isolation, so they are listed for you to judge rather than reduced to a colour.
